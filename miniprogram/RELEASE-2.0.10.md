# 2.0.10 — 指南页可以就地切换语言

日期：2026-09-20。基于 2.0.9 收尾提交 `9f8c890`；功能提交 `2db1e3e`。

## 这一版改的仍然是网站，不是小程序

2.0.9 给网站加了 `/chapters` 与 `/sanctuary` 两个指南页，但它们**只能读**语言：服务端按国家/`Accept-Language` 决定首帧语言，本地存储里用户已选的语言在 hydration 后接管——页面上却没有任何地方可以改。一个从搜索结果直接落在这两页的访客，想换语言只能先回首页切一次，再走回来。

2.0.10 把首页页头那个同款语言控件搬到这两页的页头，就地可切。**小程序一个文件都没动**（56 个受保护文件、9 个模板绑定契约、12 个数据库文件逐字节一致，见「验证」一节）。

## 改动内容

- **新增 `app/components/LocaleSelect.tsx`**：语言选择控件。三种语言的名称一律用该语言自己的写法（简体中文 / 繁體中文 / English），在任何页面、任何语言下都是同一组字符串——**它们是专有名词而不是文案**，所以放在控件里。无障碍名称（`sr-only`）由调用方传入，控件本身不含任何文案。
- **`app/components/GuidePage.tsx`**：页头改为「品牌 + 动作行（语言控件 + 返回链接）」。动作行直接复用首页已有的 `.header-actions` 几何，因此两个页头的排布完全一致；返回链接保留了它作为 `legal-header` 直接子元素时得到的颜色规则（移进包装层后原本会丢掉）。新增 `changeLocale()`，写入的键与首页完全相同（`lifescale:locale`），所以两页对「访客要哪种语言」的回答是同一个。
- **两个指南页各新增一个文案键 `language`**（中英各一份：`界面语言` / `Interface language`），用于控件的无障碍名称。
- **`app/globals.css`** 末尾新增 2.0.10 区块，只有两条规则：返回链接的颜色，以及 ≤760px 时隐藏页头字标（与首页页头在同一宽度做的同一处让步，否则品牌与语言控件要抢同样的约 300 像素）。

## 为什么单独拆出 LocaleSelect

2.0.9 的测试里有一条硬性断言：`GuidePage.tsx` 里**不能出现任何一个中文字符**——正是这条性质让同一个组件能服务两份文档、三种语言。把「简体中文 / 繁體中文」写进这个组件会直接破坏它。拆出控件既保住了这条性质，也让这三个字符串不再散落在多处（首页与引导页此前各自重复过一份）。

## 严格保留

- 相对 2.0.9 基线，**改动集合恰好是 4 个文件**：`app/chapters/page.tsx`、`app/components/GuidePage.tsx`、`app/globals.css`、`app/sanctuary/page.tsx`；受保护文件 **120 → 121**（新增的控件已显式列入白名单，不是靠目录遍历混进来的）。
- **9 个模板绑定契约 9/9 逐字未变**；小程序 56 个受保护文件与 12 个数据库文件逐字节未变。
- 新样式只读一个既有令牌（`--green-2`），**没有新色值、新自定义属性、远程资源、滤镜或动画**，明暗两套主题自动生效。首页、法务页、账号注销页、第三方页全部未触碰。

## 验证

- **全量测试 258 项：218 通过、0 失败、40 跳过。** 跳过的是 2.0.7（9 项）、2.0.8（13 项）、2.0.9（18 项）展示层基线的版本门控断言，随版本号自跳，属其设计行为。
- 新增 `tests/web-guide-locale-210.test.mjs`（16 项）：121 个受保护文件 SHA-256；相对 2.0.9 基线的变化集合**恰好等于**上面那 4 个文件（新增文件单列一条断言，既要求在清单里、也要求不在上一版清单里）；小程序 56 个与数据库 12 个逐字节不变（并断言两个集合非空，避免 glob 失效后空跑）；9 个模板契约冻结；`GuidePage.tsx` 仍为零中文字符、控件三个选项齐备、无障碍名称由外部传入；**选择器提供的语言必须与 `lib/types.ts` 的 `Locale` 联合类型完全相等**（不能只靠类型断言蒙混）；两页中英文案键逐项等量（含新增的 `language`）；新样式无字面色值、引用的令牌都已被声明、且带上了那两条响应式规则。
- **反证（确认测试真的会红而不是空过）**：
  - 给选择器加一个应用不支持的语言 → **3 项失败**。
  - 让一个不在本版范围内的受保护文件（`lib/i18n.ts`）漂移一个字节 → **2 项失败**。
- **本地生产构建 + 真实浏览器实测 44 项全通过**（`next start` + 已安装的 Chrome，未下载任何浏览器）：
  - 两页均能渲染出语言控件，三个选项为 `zh=简体中文 / zh-TW=繁體中文 / en=English`。
  - 把选项切到 English 后，`h1` 由「把日子分成章」变为「Divide the days into chapters」、返回链接由「返回余生有刻」变为「Back to LifeScale」、无障碍名称变为 `Interface language`，且 `localStorage` 写入了 `lifescale:locale = en`。
  - **刷新后仍是英文**，证明选择被记住了（与首页读的是同一个键）。
  - 760 / 375 / **320**px 三档宽度下：无横向溢出、品牌与控件不重叠、仍在同一行、控件未被裁切。
  - 两页均无脚本错误。
  - 截图存于 `个人知识库/03-项目/lifescale-2.0.10-语言选择器验收/`。
- **本地服务端渲染核对**：`Accept-Language: zh-CN` 得到 `lang="zh-CN"`、`h1=把日子分成章`、无障碍名称 `界面语言`、默认选中 `zh`；`en-US` 得到 `lang="en"`、`Divide the days into chapters`、`Interface language`、默认选中 `en`。
- 两套 ESLint、`tsc --noEmit`、`next build` 全部通过；构建产物中 `/chapters` 与 `/sanctuary` 仍为动态路由。

## 尚未验证 / 待决

- **页头品牌位置**（既有问题，非本版引入）：`.legal-header > a { justify-self: end }` 本意是给返回链接定位，但 `Brand` 渲染出来的也是 `a`，于是也被推到第 1 列右端。实测 `/privacy` 品牌位于 `[1170..1308]`、返回链接 `[1308..1380]`，与该规则一致——**法务页早就是这样**。2.0.10 只是让右侧这一簇变宽（多了语言控件），观感上更明显。若要修，`app/globals.css` 里改成 `.legal-header > a:not(.brand)` 即可，但会同时改变 `/privacy`、`/terms`、`/third-parties`、`/account-deletion` 四页外观，因此**未擅自改动**。
- 繁体（`zh-TW`）下的行为沿用首页同一控件：OpenCC 会把选项文字一并转换（`简体中文` 显示为 `簡體中文`）。这是既有行为，两个控件保持一致；若希望语言名称永不转换，`lib/use-traditional-chinese.ts` 已经有 `.ignore-opencc` 逃生门可用。
- 指南页仍**没有**深色/浅色主题切换按钮（首页有）。本版只加了语言控件，未扩大范围。
- 小程序 2.0.8 三页的实际渲染验收仍未做：自动化通道已验证可用（开发者工具自动化端口可连、首页在 iPhone 12/13 Pro 视口下正常渲染、0 异常），但圣所三页需要**已登录的小程序会话**，未登录时 `requireSession()` 会按设计把深链重定向到首页，因此必须先由人扫一次码登录，之后可由脚手架一键抓完三页。
