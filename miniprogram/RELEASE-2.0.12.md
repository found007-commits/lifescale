# 2.0.12 — 隐私政策终于承认精神圣所存在

日期：2026-09-20。基于 2.0.11 收尾提交 `543c896`；功能提交 `ba99c39`；基线与测试提交 `4dbe3ac`。

## 这一版解决的是「文档在说假话」，不是功能缺口

2.0.8 上线了精神圣所，它带来三件新事实：

1. 圣所可以被**公开**给其他已登录用户读；
2. 其他用户可以在致意墙上**留言**（而 1.2.2 起所有版本的隐私文案都写着「不允许其他用户留言」）；
3. 分享链接在**唯一一个场景**下会带上账号标识（`shareOverride()`），而 2.0.9 已经在网站上公开说明了这个例外。

而隐私政策与隐私说明**从头到尾没提过圣所一次**（`grep 精神圣所` 命中 0）。于是两份对外的政策文件里，仍然印着两句已经被产品推翻的话：

> 记录及留言不提供公开选项，**不允许其他用户留言**。
> 记录和图片**不提供公开选项**。

**这不是漏写，是矛盾。** 一个已经会把内容公开给他人、已经允许他人留言、已经会在链接里带 uid 的产品，其隐私说明声称这三件事都不会发生。这比缺少一段描述严重得多——缺描述只是不完整，写着反话是**不实的承诺**，而且在 GDPR / PIPL 语境下「不提供公开选项」属于对处理方式的明确陈述。

## 改动内容

四个文案面各改一处矛盾、各补一节事实。

### 1. 撤回被推翻的承诺（4 处）

| 位置 | 原文 | 改为 |
|---|---|---|
| `app/privacy/page.tsx` 影像与本人留言 | 记录及留言不提供公开选项，不允许其他用户留言 | **日常**记录不提供公开选项，其他用户不能在你的记录下留言 |
| `app/privacy/page.tsx` 访问控制 | 记录和图片不提供公开选项 | **日常**记录和图片不提供公开选项；到目前为止唯一的对外公开面是精神圣所，且必须由你亲手打开 |
| `app/terms/page.tsx` 你的内容 | 记录与图片仅本人可见，不提供公开选项 | **日常**记录与图片仅本人可见，不提供公开选项 |
| `miniprogram/pages/legal/legal.js` 影像与留言 | 不提供公开记录或他人留言 | **日常**记录不提供公开选项，其他用户不能在你的记录下留言 |

改法是**加限定词、而不是删句子**。「日常记录不提供公开选项」是一句仍然为真、且用户真正需要知道的话；整句删掉反而让读者以为记录可能被公开。

### 2. 补上圣所本身（网站 + 小程序各一节）

网站：`<h2>精神圣所（可选公开）</h2>`（隐私说明）、`<h2>精神圣所与公开内容</h2>`（服务条款）。
小程序：`heading: "精神圣所（可选公开）"`（隐私）、`heading: "公开内容"`（服务条款）。

写进去的事实全部可与实现对照：

- 圣所与日常记录**相互独立**，**默认私密**；
- 公开是**本人亲手**的动作；在此之前没有任何入口能让别人读到；
- 公开后其他**已登录**用户可读墓志铭与信条、可在致意墙留一条致意；
- 访客**看不到**主人的显示名称、邮箱、出生日期、目标年龄与篇章信息；
- 致意由访客**本人**撰写，署名与计数由服务端按访客账户记录，**不能代填他人身份**；
- **每位访客每小时最多 20 条**；
- 可以**随时改回私密**，改回后他人立即无法读到；
- **注销账号**会删除圣所内容与致意。

### 3. 公开说明分享例外

1.2.3 立的规矩是「分享一律为品牌标题 + `/pages/index/index`、不带任何账号 ID」。2.0.8 的 `shareOverride()` 给它开了一个例外，2.0.9 只在**网站**上说了。本版把例外写进**两个政策面**：

> 默认分享只分享应用本身、不带任何账户标识；唯一例外是当你本人查看自己已公开的精神圣所时，分享链接会带上你自己的标识……把圣所改回私密后该链接随即失效。

在小程序侧同样写进了「自主分享」一节（原文只说了分享卡生成方式）。

### 4. 隐私说明的总述句补一个例外

> 余生有刻是一处私密的个人空间。记录和图片仅登录用户本人可见……**唯一的例外是你在精神圣所里亲手公开的内容，规则见下文。**

这句话原来是绝对句，加上例外后它重新变成真的。

### 词典的删与补

`miniprogram/utils/locale-dictionary.json` **520 → 523** 条。

- **删 5 条孤儿**：被撤回的旧句子（含「不提供公开记录或他人留言」）在新文案里已不存在，留着就是一份会误导下一次改文案的假词条；
- **补 8 条中英对照**：新增的圣所与公开内容段落。

手工抄写这些句子（有的近 300 字）极易出错，所以用脚本从 `legal.js` **按标识符解析出完整中文句**作键，再写回词典——键与代码里的字面量必然逐字相同，不存在抄错的可能。繁体由 `scripts/build-mini-locales.mjs` 的 `convert(zh)` 自动产出，只需补中英两份。

### 第 9 条断言本身修过两次

这条断言（「政策不能声称数据库没强制的事」）第一版有**两个 bug**，值得记下来：

1. 迁移文件头部注释里写着 "grants nothing to anon"，朴素检索会把这句话读成相反的意思 → **先剥注释**（`replace(/--[^\n]*/g, '')`）。
2. 改完之后仍失败：正则命中的是 `insert in**to public**.sanctuary_tribute_limits` 里的 "to public"——模式少了起始词边界，而 `public` 又恰好是 schema 名。

修法是**不再对整份文件做否定匹配**，而是：

```js
const grants = migration.split(';').map(s => s.replace(/\s+/g, ' ').trim())
  .filter(s => /\bgrant\b/i.test(s));
assert.ok(grants.length > 0, 'expected the sanctuary migration to grant something');
for (const grant of grants) {
  assert.doesNotMatch(grant, /\bto\s+(anon|public)\b/i, '...');
}
assert.ok(grants.some(s => /\bto\s+authenticated\b/i.test(s)), '...');
```

多加的两条是防**空过**：一份「什么都不授予」的迁移也能让原来的 `doesNotMatch` 通过，而那正是这条测试要抓的回归。
