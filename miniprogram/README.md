“余生有刻”是 LifeScale 旗下的原生微信小程序，口号为“看见余生，认真今天”。它复用 `app.lifescale.space` 的 Supabase 用户、邮箱验证码、人生刻度、每日记录和 7 天报告数据。

## 2.0.13 四个法务页终于能变深色（2026-09-20）

- **这一版只改网站，修的是一个「沉默地不生效」的问题**：`/privacy`、`/terms`、`/third-parties`、`/account-deletion` **永久浅色**——无论系统偏好还是在首页选过深色都无效。详见 [RELEASE-2.0.13.md](./RELEASE-2.0.13.md)。
- **根因**：主题靠 `document.documentElement.dataset.theme` 生效，而唯一设置它的 `useTheme()` 只在首页 / 仪表盘 / 指南页被调用，**`LegalPage.tsx` 从未调用**，`layout.tsx` 也没有初始化脚本。2.0.11 让指南页能变深之后，同一个页头家族里出现了两套行为。
- **修法**：在 `layout.tsx` 的 `<head>` 里加一段**绘制前执行**的主题脚本（读同一个 `lifescale:theme` 键）。放在 layout 而不是给 `LegalPage` 加 hook——**主题属于文档，不属于某一页**；顺带消掉了其余页面本来可能的首次绘制白闪。
- 法务页页头加上同款主题按钮（新组件 `ThemeButton.tsx`，客户端组件，**`LegalPage` 仍是服务端组件**，套路与 2.0.10 的 `LocaleSelect` 相同）。返回链接移进共用动作行，故 2.0.10 那条规则**从 `.guide-header` 放宽到 `.legal-header`**——一条规则管两个页头。
- **一处硬编码色值必须跟着走**：`.legal-content p` 的 `#51685d` 在浅色底是 5.53:1（保留原样），在深色底只有 **3.03:1**（低于正文 4.5:1）。加深色覆盖改用令牌，线上实测 **9.19:1**。
- 保护清单 **121 → 122**（新增 `ThemeButton.tsx`，**一个没丢**）；`changed` 恰好 3 个文件；9 个绑定契约逐字未变；**小程序与数据库 0 改动**。
- 新增 `tests/web-legal-theme-213.test.mjs`（13 项）。其中一条断言**脚本必须渲染在 `<head>` 内**——只查常量名的话，脚本被挪进 `<body>` 也照样绿。另一条断言**初始化脚本与 `useTheme` 读同一个存储键**：两个读取者漂移正是这个 bug 回来的方式。
- 真实浏览器验收**本地与线上各 17 项全过、0 问题**；发版门禁新增 2 条 CSS 标记 + 4 条服务端渲染标记，**部署前反证**确认本版标记为 0 且退出码 1。
- ⚠️ **小程序旧五页的配色统一没有做，而且调查推翻了原先的前提**：那批色值**不全是漂移**。`dashboard.wxss` 的「温和 / 清醒」两种模式是**产品设计**，`index.wxss` 的宣言色块（`#123f31` 底）是**品牌块**——这两处不该动。真正留在旧世界的是 **5 个页面**（`index` / `auth` / `settings` / `entry` / `legal`）+ `app.wxss` 的旧选择器段。旧调色板（浅：`#f3efe5` 暖米白 / `#123f31` 墨绿 / `#d99b2f` 暖金；深：`#0f1c17` 墨绿黑 / `#192a22` 墨绿卡）与 `.ui-207` 令牌（浅：`#f5f5f7` / `#1c1c1e`；深：`#0a0a0c` / `#151518`）**是两套不同的颜色**。实测该批文件共 **6 个文件、149 处色值字面量（去重 91 个）**——迁移**必然改外观**，属视觉改版而非等价替换，需单独一版逐页过目。
- 顺带在旧五页的深色路径上查出**三处客观缺陷**（与审美无关；以下为代码层推算，**尚未实机渲染确认**）：① `entry.wxml` 的 `.reply-preview` 里那行 `<text>` 无颜色类、继承 `page` 的浅色，而底色写死 `#e3ece3` → 深色下 **1.07:1**，等于看不见；② `settings.wxss` 的 `.account-note`（`#8b716c`）没被 `app.wxss` 的深色块覆盖 → 深色下 **3.90:1**，低于正文 4.5:1；③ `entry.wxss` 的 `.comment` 分隔线 `#c7d1ca` 在深色底上是 **11.18:1** 的亮线，刺眼但不影响可读性。另：模拟器**没有可靠手段触发系统深色偏好**，故小程序深色相关问题目前只能从 CSS 推算。
- 流程上有个有利事实：`app.wxss` 与**全部页面 `.wxss` 都不在受保护清单内**（122 个受保护文件只冻结 `.js` / `.json` / `.toml` / `.sql` / 网站侧 `.tsx`，加 9 个 `.wxml` 绑定契约）。所以纯样式改动不碰红线；但按「逐版本冻结基线」的规矩，**仍须推版本号 + 重建基线**，否则旧版保护会随版本号静默跳过。

## 1.2.0 多图记录（2026-09-07）

- 网页多选图片，小程序每次可选 9 张并可继续添加；保存前可逐张移除，记录中点图可查看整组相册。
- 不再按原文件 10 MB 拒绝选择。大图提示处理/上传较慢，在本机转为最长边不超过 2560px、5 MB 内的静态 JPEG，然后上传私有存储。未改变原文件，云端保存优化后的副本。设备仍有解码与内存限制，失败时明确提示，不承诺无限大小。
- 网页接受 JPG、PNG、WebP、GIF、AVIF、BMP；HEIC/HEIF 取决于设备解码支持。小程序相册格式由设备决定。动图取单帧，透明区域变为白色，移除源图片元数据。
- 记录与每张照片使用稳定 ID；失败后重试当前窗口的剩余上传，已完成照片不重复上传。关闭页面不会保留尚未上传的本机选择。
- 网页与小程序共用排版引擎。图文分开采用完整、不裁切的相册排版；文字镶嵌可选择背景，多个照片时整组相册保留在文字后。通常一张长图，超过 7200px 自动完整分页；每页可选择保存/分享，不截断文字或漏图。
- 保留微信内长按保存/发送和小程序原生图片分享；不创建公开记录，不自动发布到任何社交平台。
