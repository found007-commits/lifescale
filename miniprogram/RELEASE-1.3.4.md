# 1.3.4 — simpler sharing with optional metadata and signature

- Fixed bottom actions: Send to a friend and Save image remain reachable while scrolling the preview. Safe-area padding keeps actions above the home indicator. The bar is hidden while editing the text/photo selection. Multi-page cards show the selected page number.
- Collapsed Share settings contains Show date, Show mood and category, and Sign with my nickname. Date/tags retain their previous defaults; signature is always off for a newly opened share. No settings persist between shares.
- Signature uses only the existing profile display name after an explicit toggle. No account email, account ID or synthetic login identity is used as a fallback. Missing nickname leaves the toggle disabled with a Preferences hint. Long nicknames fit on one line with ellipsis; the full nickname is shown beside the choice before sharing.
- Metadata switches rebuild the allowlisted share copy and regenerate every exported image in both layouts. Old images are removed from preview and temporary files before regeneration; sending/saving is blocked during edits, rendering, saving and an active native send operation. A failed render cannot send an old image.
- The stored entry, profile, selected text/photo editing, original-image order, multi-image layouts and complete long-image pagination are preserved. Date/mood/category hidden in the settings are omitted from the rendered copy, not merely the screen UI.
- Original records remain private. No public square, public visibility change, community interaction or promise of download/screenshot prevention. No original/repost/AI declaration controls in this focused release. Native WeChat may show additional destinations; the app does not automatically post to them.
- No web production deployment, database migration, authentication change or real-account content access. The shared renderer keeps previous web defaults; only explicit new options alter metadata/signature.
- Validation: 95 automated tests, TypeScript, ESLint and Next.js production build passed. Actual renderer tests cover both layouts, 720/1080 widths, nine photos, multi-page long text, bounded nicknames, metadata exclusion and stale-image prevention. Tests also cover unsigned defaults, missing nickname, editor retention and native send cancellation.
- Native DevTools: verified collapsed/expanded settings, fixed bottom actions, the disabled missing-nickname toggle, both metadata switches, opt-in synthetic nickname, multi-photo overlay footer, and English labels with a text-only sample. Only virtual records and the bundled brand icon were used, with no remote content reads/writes or actual sends/saves. Console input syntax errors during initial fixture entry were corrected; the tested page interactions produced no runtime errors (simulator resource/worker warnings remain). Phone-native recipient selection and album permission still need real-device acceptance.
